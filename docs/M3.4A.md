## Préparation des séries

Les cinq types existants restent disponibles : travail, échauffement, top set, back-off, personnalisée. Le numéro suit la position dans l’exercice ; les identifiants stables ne changent pas lors d’une réorganisation. Nom libre, suggestions de noms facultatives, répétitions exactes/plage, charge/RIR facultatifs, repos individuel et notes restent indépendants. Choisir une suggestion de nom ne change pas le type de série.

L’éditeur ordinaire reste manuel. Pour un échauffement ou un back-off, ouvrir **Charge calculée (facultatif)**, puis sélectionner **Pourcentage d’une série prévue**. La référence n’est jamais choisie automatiquement. Les choix montrent numéro courant, nom/type et charge, même si le réglage général masque habituellement les numéros.

- Échauffement : référence manuelle de type travail, top set ou personnalisée, dans la **même occurrence d’exercice**.
- Back-off calculé : référence manuelle de type top set, dans cette même occurrence.
- Une référence peut se trouver après l’échauffement dans l’ordre prévu. Son identifiant, pas son numéro, porte le lien.
- Les calculs en chaîne sont interdits. Une série calculée ne peut pas servir de référence et aucune série ne peut se référencer elle-même. Les contraintes SQLite protègent aussi ces règles.
- Pourcentage numérique strictement supérieur à 0 et inférieur ou égal à 100. Le clavier accepte la virgule française.

**Remplacer par une charge manuelle** retire le lien lors de l’enregistrement et reprend la proposition courante comme valeur éditable. Un back-off ou un échauffement peut toujours rester entièrement manuel. Aucun ajout automatique de séries ni progression imposée.

## Convention de calcul

`cible calculée = charge cible manuelle de référence × pourcentage / 100`.

Exemples : 80 kg × 50 % = 40 kg ; 100 kg × 90 % = 90 kg ; 83,25 kg × 12,5 % = 10,40625 kg. Les représentations décimales sont multipliées par entiers, puis converties une fois en nombre JavaScript / SQLite REAL. Il n’y a aucun arrondi à un incrément de matériel ni au dixième/centième de kg. La précision finale reste celle d’un nombre IEEE 754, pas une arithmétique de précision arbitraire. Les objectifs calculés sont affichés sans troncature volontaire à trois décimales. Une valeur impossible à représenter est refusée.

Charge de référence absente : cible calculée **null**, jamais 0. Une référence explicitement à 0 donne 0. L’utilisateur peut conserver une règle avec une référence existante sans charge ; l’interface annonce cette absence et les résultats réels restent libres. Après suppression de la référence, le lien devient explicitement manquant et la cible reste null ; choisir une nouvelle référence ou passer en manuel pour éditer cette règle. La confirmation de suppression avertit des séries dépendantes.

Modifier la cible de référence actualise les préparations qui la suivent. Changer son type vers un type incompatible est refusé tant qu’elle sert de référence ; enlever les liens d’abord. Les lectures calculent les cibles à partir des valeurs courantes, sans stocker une deuxième charge dérivée susceptible de devenir périmée.

Les trois modes sont respectés : pour une charge totale, par haltère ou ajoutée, le pourcentage s’applique à cette même unité. Les références inter-exercices sont interdites ; aucun doublement des haltères ni estimation du poids du corps n’est effectué. Le remplacement d’un exercice prévu conserve les avertissements M1.1 de vérification des objectifs et du mode. Un remplacement temporaire M2 continue de vider les cibles de charge restantes, sans recalcul automatique sur le nouvel exercice.

## Affichage et préférence

Paramètres propose **Numéro uniquement**, **Nom uniquement**, **Numéro et nom**. Le défaut conserve la présentation M3.3 : nom libre ou type, avec repli « Série N » pour une série de travail sans nom. Numéro et nom donne par exemple « Série 2 · Top set ». Le réglage s’applique aux vues prévues, à la série active, au bilan et aux tableaux d’historique. Les compteurs de progression et l’ordre réel restent visibles indépendamment des noms.

Clé locale `series_display` dans `app_preferences`, valeurs JSON `number`, `name`, `both`. Sans ligne, défaut `name`. Le provider d’affichage est indépendant de celui du son, dont le comportement n’est pas modifié. Les écritures rapides sont ordonnées ; une erreur du dernier choix revient au dernier réglage confirmé et propose Réessayer. Une préférence de présentation ne réécrit aucune série ou performance historique.

## SQLite v5 → v6 et export

Migration transactionnelle additive, sans UPDATE des anciennes données :

1. `set_load_rules` : clé `set_template_id` vers la série prévue (`ON DELETE CASCADE`), `reference_set_id` nullable (`ON DELETE SET NULL`), `percent`, `basis = planned_target`. Contrôles de type, portée, référence manuelle et absence de chaîne.
2. `session_sets.load_rule_snapshot` : JSON nullable, protégé contre toute modification. Les anciennes séries restent null ; les séries manuelles restent inchangées.
3. Préférence d’affichage dans la table existante ; aucune valeur ajoutée avant un choix utilisateur.

Au démarrage d’un entraînement, les cibles sont résolues dans la transaction de capture, puis stockées dans `original_targets` et les objectifs courants. La provenance conserve ID de référence prévue, pourcentage, base planifiée, cible de référence, résultat et mode de charge. Les séances déjà actives/terminées ne sont pas recalculées. Les performances restent exclusivement les nombres validés par l’utilisateur. Supprimer le programme conserve tous ces instantanés.

L’éditeur manuel d’entraînement déjà livré en M1.2 reste disponible : **Cette séance** ne touche pas le programme ; **Programme** remplace explicitement une règle de charge par la cible manuelle saisie. Un texte le précise pour une série capturée avec calcul. L’opération reste transactionnelle et n’altère jamais la provenance initiale ni une série réalisée. Aucun nouvel éditeur de pourcentages en séance n’est livré ici.

L’export conserve son enveloppe **format 1**, avec `sqliteSchemaVersion: 6`, **15 tables**, les règles, leurs références, les instantanés et la préférence. La convention de calcul est ajoutée aux métadonnées. Le traitement par lots, l’instantané cohérent et la feuille native restent identiques. **Aucun import/restaurateur n’est livré.** Voir [format](FORMAT_EXPORT_PERSONNEL.md) et [restauration V1](RESTAURATION_V1.md).

Les versions M3.3 et antérieures refusent une base v6 sans l’effacer. Après installation, rester sur M3.4A ou une version ultérieure. Même `logbook.db`, identité Expo et dépendances. Aucun reset ni programme préinstallé.

## Statistiques et suite M3.4B

Conventions M2/M3 conservées : tonnage sur charges réellement saisies × répétitions, échauffements inclus ; charge absente exclue ; aucun doublement des haltères ni poids corporel estimé. Les graphiques de charge/répétitions retiennent une série hors échauffement, selon les règles M3.1. Le RIR absent reste exclu de sa moyenne. Les nouvelles cibles calculées ne participent jamais à ces statistiques avant une validation réelle.

M3.4B devra traiter l’ajout de séries pendant un entraînement, les règles fondées sur une performance réellement validée et leur édition avancée avec portée explicite. Il devra préserver les instantanés et types des séries déjà réalisées, définir les réactions aux remplacements, à une référence sautée et à une charge réelle absente, sans modifier silencieusement le sens des historiques. Aucune fonction correspondante n’est simulée en M3.4A. M3.4C couvrira les fiches pédagogiques ; Cardio, 3D, coach et refonte globale restent hors périmètre.
