# M0 — programmes et séances locales

## Périmètre

M0 prépare le socle de l'application iPhone : Expo, React Native, TypeScript, Expo Router, thème sombre et stockage local avec `expo-sqlite`. Il couvre les écrans **1 à 4** de la maquette : accueil, programmes, détail d'un programme et séances d'un programme.

Les formulaires permettent de créer et modifier un programme et ses séances prévues. Ils enregistrent les noms ainsi qu'une description de programme ou des notes de séance facultatives. Les noms sont limités à 80 caractères, les descriptions et notes à 1 000 caractères. Les champs sont contrôlés dans les formulaires et dans la couche de stockage.

Le premier lancement est vide. Les noms, programmes, performances et statistiques présents dans la maquette ne sont pas des données préinstallées. Les seuls comptes affichés pour les programmes et les séances proviennent des données réellement créées par l'utilisateur.

## Design et navigation

La référence est la [maquette validée](design/Maquette%20d’application%20fitness%20complète%20en%2021%20écrans.png). M0 reprend son fond sombre, ses accents bleus, ses bordures discrètes, ses cartes arrondies, la hiérarchie des textes et des actions. L'accueil reprend la disposition générale de l'écran 1, avec les cartes de progression et de séance adaptées à l'absence d'entraînements réalisés. Une séance prévue n'est jamais comptée comme une séance réalisée ; aucun graphique, poids soulevé ou résultat sportif fictif n'est affiché.

L'accueil et l'univers Musculation partagent un conteneur vertical plein écran. Un glissement vers le haut fait monter l'accueil sous le doigt et dévoile Musculation depuis le bas. Le glissement inverse ramène à l'accueil. Un geste court peut être annulé ; des boutons accessibles déclenchent la même transition verticale. Les listes conservent leur défilement, avec un retour à l'accueil possible depuis le haut de la liste des programmes. Les formulaires et les détails de programme restent hors de ce conteneur : les gestes entre univers ne les ferment pas.

La navigation s'appuie sur React Native Gesture Handler et Reanimated, déjà présents dans le projet Expo. Un registre décrit l'ordre des univers afin de préparer l'ajout ultérieur de Cardio, sans activer un troisième écran ni développer ses fonctionnalités dans M0. Le réglage iOS **Réduire les animations** est pris en compte.

Le détail du programme propose une action explicite **Voir les séances**. L'écran 5 sert à préparer la suite du parcours, sans construire de suivi d'entraînement. Les visuels musculaires 3D et les calculs de performances de la maquette attendent leurs futurs jalons.

## Architecture

| Emplacement | Rôle |
| --- | --- |
| `app/` | Routes Expo Router : accueil, programmes, détail et formulaires, séances du programme. |
| `src/navigation/` | Conteneur vertical des univers, état de navigation, arbitrage des gestes et décision de fin de glissement. |
| `src/domain/` | Types des programmes et séances prévues. |
| `src/db/` | Schéma, migrations versionnées et opérations SQLite. |
| `src/store/` | Accès aux données depuis l'interface et actualisation après sauvegarde. |
| `src/features/programs/` | Formulaires et états de chargement, validation des saisies. |
| `src/ui/` | Thème et composants d'interface réutilisables. |
| `tests/` | Tests SQLite, formulaires, règles de geste et intégration du pager. |

Les données de M0 sont des **préparations**, pas un historique d'entraînements : un programme contient des `WorkoutTemplate` ordonnés. Une future `WorkoutSession` représentera une séance réellement commencée et sera distincte de ces modèles. Cette séparation permettra de modifier une préparation sans réécrire les performances passées.

La base n'ajoute que les tables nécessaires aux programmes et séances de M0. Les tables d'exercices, séries, séances réalisées, repos et historiques seront introduites par des migrations lors des jalons concernés. Les identifiants stables, les liens entre programmes et séances et les migrations versionnées préparent ces évolutions sans construire des fonctions inutilisées dès maintenant.

Aucun compte, serveur, secret ou API externe n'est requis pour les données de l'application. La persistance est locale sur l'appareil, sans données de démonstration.

## Vérifications reproductibles sous Linux

Avec Node.js 24 et après `npm ci` :

```bash
npm run typecheck
npm test
npm run export:ios
```

`typecheck` vérifie la cohérence du code TypeScript. Les 42 tests comprennent 12 tests sur une vraie base SQLite (moteur de Node), 13 tests des règles de geste, 9 tests de formulaires/états vides et 8 tests d'intégration du pager. L'intégration monte le vrai pager, ses contextes, son ScrollView et le dispatch Gesture Handler ; elle vérifie notamment le déplacement avant relâchement, l'annulation, la priorité des listes, les boutons accessibles et un futur troisième univers. L'animation est simulée en JavaScript et le stockage des tests d'interface est simulé : ces tests ne prouvent pas la fluidité, l'arbitrage UIKit ou le fonctionnement de `expo-sqlite` natif sur iPhone.

`export:ios` assemble le JavaScript et les ressources pour iOS dans `dist/ios`. Il ne produit pas un fichier `.ipa`, ne compile pas les dépendances natives et ne valide pas leur comportement sur appareil. Le dossier généré n'est pas une livraison App Store.

La [CI GitHub](../.github/workflows/ci.yml) reproduit l'installation et ces vérifications sur Node.js 24. Le [guide iPhone](TESTER_SUR_IPHONE.md) contient le parcours manuel, notamment la mise à jour sans effacer les programmes et les gestes à essayer. La création, la modification et la persistance de la première version ont été validées par l'utilisateur sur un véritable iPhone avec Expo Go. La nouvelle transition et le nouvel accueil restent à vérifier sur cet appareil ; Linux ne permet pas de lancer le simulateur iOS.

## Limites et suite

- Aucune exécution de séance, bibliothèque d'exercices, configuration des séries, saisie de charge ou répétitions : **M1**.
- Aucun chronomètre, alerte de repos ou reprise d'entraînement en cours : **M1**.
- Aucun bilan, graphique de performances ou historique d'entraînements : **M2–M3**.
- Aucun mannequin 3D, carte musculaire calculée, progression automatique, fonction coach ou synchronisation : **M4**.
- Aucune suppression ni archive depuis l'interface de M0.
- Aucun export de sauvegarde ni restauration sur un autre appareil. Désinstaller l'application ou Expo Go peut effacer les données locales.
- Le prototype est destiné aux essais avec Expo Go. La distribution autonome, TestFlight et App Store restent à préparer.

La prochaine étape est un parcours limité de M1 : ajouter des exercices à une séance prévue, configurer des séries indépendantes, puis enregistrer une seule série active à la fois. Les décisions produit encore ouvertes dans la spécification doivent être tranchées avant les fonctionnalités qui en dépendent.
